# FB17 — personal native widget recipes

The original Clock/Weather stage is recorded below. The local 0.5 extension adds
[Calendar and system recipes](PERSONAL-WIDGETS-050.md) with versioned transport.

Clock and Weather can now be composed in **Widgets → Builder**. Choose native
parts, reorder them, set compact/wide arrangements and check a missing-data sample.
**Save widget** changes the local library; **Apply to Clock/Weather** updates that
existing desktop widget through the guarded store and supports Undo. **Use built-in**
restores its original composition. This stage does not expose duplicate instances.

Recipes preserve Clock face/type choices and reuse the existing Weather observation.
They contain a bounded caption, native parts and one approved Settings action.
Previews use samples. Missing, stale and failed Weather states remain visible; a
small surface keeps the main reading rather than shrinking every part. Ridge depth
yields to a personal Clock composition while preserving its saved intent.

A saved revision binds all recipe content. Applying embeds that exact snapshot, so
editing or deleting its library entry cannot alter a desktop, saved setup or Undo.
The private library admits 32 entries, 512 KiB total; each recipe has at most eight
parts and 16 KiB. Commands, arbitrary bindings, URLs and asset paths are not supported.

Personal recipes require the explicit widget migration. Design schema 2 and profile
format 13 keep their semantics distinct from older files. The retained FB16 build
refuses a personal design without rewriting it. Private legacy export refuses active
personal recipes; explicitly restoring built-ins makes that export available again.
Older ordinary profiles keep their existing version.
