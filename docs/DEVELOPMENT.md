# Halcyon: developer reference

> Names and paths changed with the rename: the program is `halcyon`, the
> controller `halcyon-ctl`, the service `halcyon.service`, and per-person
> folders are `~/.config/halcyon` and so on. Where this document still says
> `cosmic-desktop-cards` or `desktop-cards`, read the new names;
> [packaging/README.md](../packaging/README.md) is authoritative. Test with
> the serial commands in [Build and development](#build-and-development).

How Halcyon (formerly Desktop Cards; the code and paths still use that name until the rename) is built and how its parts work. For what it is and how to install it, see the [README](../README.md). It ships thirteen wallpapers: seven Halcyon scenes and six procedural palette gradients (see [ASSETS.md](../ASSETS.md)).

The clock and selected cards stay above the wallpaper and below application windows. The default layout places Clock in the upper-left corner; it lets pointer input pass through. Calendar has its own interactive surface, vertically centered on the left in the default layout. Weather, Devbox and Projects form an independently centered right column by default. All five widgets can also be positioned freely in the desktop arrangement editor. Only the control sidebar slides in, over the cards and application windows; revealing it does not move any widget. Normal desktop surfaces never take keyboard focus or reserve screen space. The arrangement editor temporarily takes focus until Save or Cancel.

Each widget has its own refresh interval in Settings. Defaults are three seconds for Devbox, thirty seconds for Projects, five minutes for Calendar, fifteen minutes for Weather, and one minute for Clock. Clock updates align to the wall-clock minute; Calendar highlights and midnight changes continue locally even with a long Google refresh interval. Failed updates retain the last successful data. Calendar and Projects show the stale state; Weather keeps its last reading without saved-data labels or timestamps. Weather uses Open-Meteo, Celsius and km/h, and the city chosen in Settings.

## Getting started

Open **Desktop Cards** from the launcher. Layout offers **Set up**, which opens a short checklist: show widgets, choose whether to start at login, pick a weather city, choose a look, and optionally connect Calendar. Projects asks for folders; Music follows a playing browser or media app; Notes and Focus work locally without accounts. **Widgets** shows which cards need setup. Skip the checklist whenever you like, and reopen it from **App settings → Show setup**. The system monitor starts with hardware stats; personal T3/Voxtype service indicators are off until enabled.

## Settings

Settings follows the current COSMIC light/dark theme, accent, fonts and control styling. Changing the cards’ palette changes the widgets and their previews, without recoloring the Settings window.

- **Layout:** move, resize and align desktop cards. Select a card to customize it; layout changes use Save and Cancel.
- **Widgets:** show or hide cards and open their settings. Combine Clock, Weather and Calendar into Daily overview here. Widget style is on this page; each card keeps its own settings.
- **Desktop:** Wallpaper & colors, Theme & fonts, Dock & panel, Windows & workspaces, Shortcuts and Accessibility. Each editor keeps its existing Apply and Undo behavior.
- **Themes:** one look for widgets, dock, panel and windows. Presets & schedules opens existing layout presets and automation.
- **App settings:** startup, edge controls, setup and recovery.

Dock & panel also offers optional **Islands** with Together or Separate placement, adjustable gaps and temporary native drag handles. It requires the pinned companion panel component; see [setup and stock restoration](../companion/README.md). The ordinary dock stays the default.

The back button and Alt+Left return to a page’s parent. Search opens the relevant editor and control. Changing pages preserves unapplied drafts; **Review changes** gathers them. Existing command-line page names remain supported.

### Shared desktop themes

Open **Themes** (`desktop-cards settings --page themes`). The page shows a live preview of your own desktop (your wallpaper, your cards where they sit, the dock, the panel and an active COSMIC window with its outline) beside the four styles, each drawn as a specimen on your wallpaper in the colors it would use. **Soft** has rounded tinted surfaces; **Outline** uses fine rules and monospace type; **Paper** has warm light cards, dark ink and a Noto Serif clock; **Bare** puts widget content directly on the wallpaper. Choosing a style only previews it. Apply keeps widget positions, sizes, visibility, content and account settings, and preserves the dock/panel's applets, ordering, anchors and visibility.

**Color** is one row of choices: **From wallpaper** follows the wallpaper, including later changes and while Settings is closed; the wallpaper's other distinct hues are fixed colors; the style's own color; and **Custom** for a `#RRGGBB` value. Style and color are independent, so changing style keeps the color choice. Wallpaper colors are toned for use: each offered color keeps the picture's hue at a lively, readable lightness, so a dark picture gives a visible accent instead of one of its dark pixels. A colorful picture offers up to four distinct hues; a grey one keeps the style's own color until the wallpaper changes. Surfaces carry a quiet tint of the chosen hue while each style keeps its own lightness, outline, corners and type. **Wallpaper** optionally includes the style's built-in gradient (**Yours** or the style's gradient); it changes the shared wallpaper without replacing display assignments, which keep taking precedence. Wallpaper text uses separately resolved light/dark ink.

The first theme starts from the color you already use: following the wallpaper stays on, an explicit fixed color is kept, and someone who never chose starts with the wallpaper's colors when it has any. Your previous appearance is kept once as **Before Themes**.

Native coordination: the dock and panel paint the style's surface; COSMIC applications get the accent, a background and a container one step lighter (darker for Paper). COSMIC's own palettes use a pastel accent in Dark and a deep one in Light, so the shared color becomes one tone per variant and stays readable in both modes. The **active window outline follows the accent** in both variants. An outline color chosen later in Theme & fonts stays through style changes until you reset it; an outline set before themes follows the accent from the next theme you apply. An outline color that only COSMIC's derived theme holds (another tool can write one) is kept too and shown as Customized until Reset. Applets retain their own fonts; light/dark mode and application fonts stay unchanged. Noto Serif falls back to the system font when unavailable. Themes work with the ordinary dock/panel; an already enabled Islands layout gets the style's gap, without installing or enabling the companion. No theme promises compositor blur.

After Apply, **On your desktop** lists Widgets, Dock, Panel and Windows (the accent and active outline) as matching the theme or **Customized**, with **Customize** for the existing editor and **Reset** for a customized one. Reset previews only that surface and uses the same Apply and Undo. Widget style also offers filled/transparent surfaces and **Improve readability** for a backing on busy wallpapers. Explicit native surface colors survive wallpaper color updates until reset; surfaces and accents applied by the previous release still count as matching and move to the current tones on the next update.

The selected look can be saved as a copy, exported, renamed or deleted from the icons beside its name; **Save current…** and **Import…** are under **Your themes**. These use the existing profile library and file chooser. **Before Themes** remains restorable and cannot be deleted through the library. Old settings keep their original rendering until a theme is applied. Themes use profile format 7, enforce an appearance-only boundary on import, and share existing conflict protection, saved drafts, recovery and Undo. Legacy profiles still export the oldest version their fields need. In capture mode the Themes command list also accepts `{"accent":"#RRGGBB"}` for a fixed color.

## Install

Requires Pop!_OS 24.04 (or another COSMIC session on Wayland), Rust 1.93 or later, and the Wayland and xkbcommon development packages.

The Notes card’s copy button also uses `wl-copy` from `wl-clipboard`, so it can copy without taking keyboard focus. Copying text in Settings uses the normal toolkit clipboard.

```
cargo build --release --locked
python3 scripts/install.py
halcyon --settings
```

`scripts/install.py` installs `halcyon` and `halcyon-ctl` under `~/.local/bin`,
helpers under `~/.local/lib/cosmic-ext-halcyon`, wallpapers and desktop integration
under `~/.local/share`, and `halcyon.service` under `~/.config/systemd/user`.
It reads `CARGO_TARGET_DIR` when set, or accepts `--binary PATH`. Open the app with
`~/.local/bin/halcyon --settings` to distinguish it from an installed system release.
First-run setup controls showing widgets and starting at login.

The installer does not enroll this build in release updates or change app
preferences. It preserves enabled/running service intent during legacy migration
and restarts an already-running Halcyon user service after replacement. To upgrade,
build and run it again; replaced executables are backed up under
`~/.local/share/halcyon/backups/<time>-install/`. There is no `--restart` option.

For a system package development test, use the explicit `--development` mode in
[the packaging guide](../packaging/README.md#build-mode). Its distinct package
identity prevents release APT updates from replacing a development build.
`--release-updates` is for reviewed release assembly only.

To remove a per-user install, stop it with `halcyon-ctl stop`, turn off **Start when
you sign in**, and remove the installed program/integration files listed in the
[packaging layout](../packaging/README.md#layout-under-a-prefix), including the user
unit and `~/.local/share/applications/io.github.profilaz3.Halcyon.desktop`. Keep
personal settings unless you intend to discard them. System package removal uses APT.

## Using it

Hold the pointer at the **far-right screen edge for one full second**, at any height, to reveal the sidebar. A shorter visit cancels opening. The edge has no visible handle, and the closed sidebar is fully offscreen. One-shot timers handle the hover and dismissal delay; animation frames run only while sliding. Moving away hides it after a short grace period. The selected widgets stay on the desktop regardless of sidebar visibility; no Pin control is needed.

All nine widgets are available: **Calendar**, **Projects**, **System monitor**, **Weather**, **Clock**, **Daily overview**, **Music**, **Notes**, and **Focus timer**. Click a name to show or hide it; a checkmark and accent background mark selected widgets. **Drag a right-side card's name up or down** to reorder that column live, then release to save. Releasing outside the sidebar cancels the drag. A drag never toggles visibility. Calendar and Clock have separate visibility toggles below the draggable rows. When custom positions are saved, sidebar and settings column reordering are disabled until positions are reset.

The selected cards stay on the desktop. Calendar is centered on the left, Clock stays at the upper left, and the right column is centered independently. Calendar fits the rendered event list, including wrapped titles: quiet days shrink and busier days grow up to the available height. Long event and project lists scroll inside their cards. Visibility and ordering are remembered across restarts.

Weather uses a compact current-conditions row and three-column forecast. Devbox keeps its stats close together. Weather uses 180 pixels. Devbox fits its enabled sections (259 pixels with all sections and one GPU). All seven section icons share a 16-pixel outline style. Every section uses the same header, spacing, and indicator height; network, uptime, and services have neutral tracks without a fabricated usage percentage. GPU memory appears in smaller text beside load and temperature. Optional swap usage also appears in smaller text beside the Memory values, without adding another line. Weather has a small timestamp beside the city, with no City button or separate update row. Calendar grows with its agenda up to the available screen height, then scrolls.

**Settings** opens on **Layout** (the older `home` command still works). Select and drag widgets directly in the picture; drag a selected card’s lower-right corner to resize. Selecting a card opens its inspector with width/height steps, **Resize with arrows**, **Fit content**, and **Customize**. Clicking empty canvas clears selection without navigating away. Layout also links directly to **Wallpaper & colors**. Every widget has a quick visibility switch below the picture. **Themes** previews the four shared families; **Presets & schedules** retains the older layout presets. Alt+Left goes to a subpage’s parent or Layout, dismissing search first; layout drafts survive navigation. Search (Ctrl+F) ranks exact terms, synonyms and conservative typo matches locally. It opens the owning page, expands the relevant details and highlights the result, including per-reading history graphs. Old command page keys remain supported.

Simple widget preferences save automatically and have a session-local **Undo** that preserves unrelated changes and refuses to overwrite a newer value. Layout uses **Save layout**; note text uses **Save**; desktop editors and presets use **Apply / Discard**. **Review changes** stays visible across pages while edits are pending; Home shows its layout draft badge without shifting the canvas during a drag. Save and Cancel appear only for a layout draft. Unapplied desktop edits, layouts, schedule forms and preset selections are recovered after closing Settings; desktop editors keep their original baselines and report conflicting outside changes. Layout saves retain concurrent changes to untouched cards; positions and dimensions you edited take precedence. A restored preset requires **Review changes** before Apply. Drafts are private local files, independent of the persistent desktop Undo journal and note drafts. Search and pointer motion do not rewrite draft files.

- **Wallpaper & colors:** one home for background pictures, six palettes, clickable wallpaper swatches and **Use best color**. **Widgets + Pop!_OS** is the default color scope; **Widgets only** is beside it. One **Apply** saves the selected app color and, when selected, both COSMIC theme accents in a recoverable transaction. Any staged wallpaper is included; choosing only colors leaves the current wallpaper unchanged. One **Undo** restores the combined change. The app keeps its own chosen color when desktop colors change elsewhere. Small widget text uses readable derived ink while Pop!_OS receives the exact chosen accent. Existing desktop-following configurations keep their read-only behavior until the next intentional color Apply.
- **Widgets → Widget style:** card previews, Soft / Solid / Minimal finishes, opacity, corners and outlines are widget-only preferences that save automatically. A compact **Wallpaper & colors** link opens the shared color editor. The existing `--page appearance` link still opens Widget style; recovered color drafts appear under Wallpaper & colors in **Review changes**.
- **Widgets:** all nine widgets in one collection, with configuration and visibility controls. **Arrange widgets** on Home (and the search result of that name) opens the full-screen editor on the desktop itself; **Arrange with keyboard** beside it opens the arrangement editor in Settings, using the active screen and actual widget sizes, and Settings opens that one instead when the desktop can't take the request (no widgets shown, or the widgets service won't start). Legacy Layout links open Home. **Automatic column order** appears when the default layout is active; manual layouts keep this inapplicable control hidden. Drag cards on the fine grid, resize from the corner, or use arrow keys / Shift+arrows in Move or Resize mode; **Save layout** applies, **Cancel** discards, and **Reset layout** previews defaults. Drafts survive visits to other pages and closing Settings. **Arrange on desktop** opens the full-screen editor, where **R** switches the arrow keys between moving and resizing. **Undo** reverses draft gestures; Escape cancels the current gesture first, then the layout. A saved layout also has session-local Undo in Settings. The default right column also supports reordering. `--page layout` opens Home directly; existing positions stay unchanged until saved.
- **My widgets → Separate cards / Combined card** chooses whether Clock, Weather and Calendar stand alone or share one movable **Daily overview** (`glance`). The combined card can be customized before enabling it. Choose Transparent or Panel, with separate panel opacity. Both Compact and Comfortable spacing show today and can include Tomorrow; changing Tomorrow keeps your chosen spacing. Every event can be reached: the agenda grows down from its fixed top edge and scrolls at the screen boundary. Clock, Weather and Calendar can each be switched off inside Glance. Turning Glance off restores the original widgets and their positions.
- **Calendar:** Today and Tomorrow are independent switches for separate cards. In combined mode this page edits the combined agenda: Today is always included, and Tomorrow is optional in either spacing. Separate-card day choices are preserved, and Undo restores the Tomorrow choice without changing spacing. Meeting-highlight timing and refresh interval are below.
- **Weather:** the current city appears beside a card preview using clearly labeled sample conditions. **Change** opens city search, which starts after a short pause in typing. Cancel invalidates pending searches and leaves the city untouched. Results show region and country; select one to apply it. Clearing the query and choosing a city invalidate pending responses, and failures can be retried without replacing the current location.
- **Widgets → System monitor** (`devbox`): drag a reading by its name or handle, or use arrows to reorder CPU, memory, disk, network, GPU, uptime, and services. Every row has a visibility switch; hidden readings retain their place. The actual card renderer previews sample readings without polling. Expand a reading to edit its details: Memory contains cache size and swap switches, and graph controls stay with their reading. Optional CPU, network and GPU history graphs show five-minute area charts: a filled area under a 1.75px line over a faint full-width track, with a dot on the latest reading. CPU and GPU graphs step their ceiling between 25, 50 and 100% (named in small muted text at the top right): a reading above the ceiling raises it at once, and it steps down only when the whole window fits under 80% of a lower step. Network draws download in the accent and upload in the muted color against one shared power-of-two scale. Memory and Disk always show bars; a saved `history.memory` or `history.disk` is kept in the file but draws nothing, and a saved memory graph with no `memory_cache` of its own turns the cache size on. Graphs are off by default and keep consistent 28px indicator slots; missing readings leave gaps and hidden readings stop collecting history. Hiding Services affects only its display and sampling, not the services themselves. Disabled sections stop their associated sampling; all sections off pauses sampling entirely.
- **Clock:** 12/24-hour time, optional date, and refresh interval.
- **Projects:** add or remove scan folders and choose a scan interval.
- **Music, Notes and Focus timer:** individual pages in Widgets (see *Desktop tools*). They start off, including after an upgrade.
- **App settings** (`general`): desktop visibility, startup, edge controls and animation, and restoration of the previous wallpaper.
- **Pop!_OS desktop:** direct sidebar entries plus a category overview with six categories: Theme & fonts; Wallpaper & colors; Dock & panel; Windows & workspaces; Shortcuts; Accessibility. Desktop items are reached from Wallpaper & colors, and workspaces / floating-app rules from Windows. Native handoffs are labelled **Open COSMIC Settings ↗**.
- **Presets:** the saved-look library and **Schedules** together. **Clean desktop** (stable ID `presentation`) hides cards and autohides the dock; it does not mute notifications. Manual review applies selected parts; schedules apply the chosen preset’s supported parts.

- **Dock & panel:** choose Dock or Panel above a preview of both bars. **Panel contents** puts Left / Centre / Right in one visual editor (Top / Middle / Bottom for a vertical panel). Drag an applet by its handle onto another applet or the space at the end of a region. Small windows use compact icons with name tooltips; selecting one shows its full name and controls. Select an applet to read its description, move it directly to a region, reorder it with **Earlier / Later**, or **Remove** it. These named controls support Tab and Enter; focus follows a moved occurrence. Escape or releasing outside a target cancels a drag. Unknown and repeated applets are kept, with unavailable applets identified in their tooltip and inspector. Screen-reader naming remains limited by the pinned libcosmic’s lack of an accessibility widget tree.
  **Add applets** opens one searchable picker, with a destination and Essentials, Media, System readings and Quick controls filters. Only installed native applets are offered. Sound includes native now-playing controls; Time & date opens the native calendar. Third-party readings or active-window applets appear when installed and discoverable. **Add another** explicitly adds a repeat; each occurrence stays separate. **Starter layout…** previews the installed essentials before replacing the panel draft: workspaces and launcher on the left, clock in the centre, and notifications, sound, network, Bluetooth, tray and power on the right. Battery is included when present. Loading the editor never resets a layout.
  Choose **Full width** or **Islands**; existing compact bars remain labeled as kept. New panel islands start separately at the left, centre and right, with rounded corners when the panel was square. The existing companion provides Together / Separate placement, gap and Arrange; apply native panel edits before arranging on screen. Saved island positions and the independent dock stay intact. Size, transparency, auto-hide, screen edge, display, floating gap, corners and background are below the contents editor. Advanced holds timing, spacing, padding, exact corner radius and maximized-window behavior. Unsupported values stay *kept* unless explicitly replaced. The dock retains its applet rows, arrow controls, installed list and appearance controls. The installed catalog refreshes on every visit; nothing is downloaded. A disabled panel keeps its editable contents and links to **Open COSMIC Settings ↗** to turn it on.
  Nothing changes until **Apply**; **Discard** drops the draft. Both bars’ drafts survive navigation and closing Settings. **Undo** restores the previous values after Apply, including after reopening. Outside edits are detected and named; **Use current value** adopts the conflicting values while preserving other edits, and **Keep my change** keeps the edit and writes it over the outside value at Apply (a value changed again after that is a new conflict). Apply and Undo refuse to overwrite newer changes.
- **Desktop → Theme & fonts**: the COSMIC theme mode (Light, Dark, Automatic) and separate Light and Dark themes. A sample window at the top shows the variant you are editing — choosing Light or Dark there only previews and edits that theme; it never switches the mode. **Wallpaper & colors** opens the common accent picker. **Advanced theme colors** keeps separate per-variant accent, window background and primary/secondary surface overrides, each a swatch with a short hex field (`#RRGGBB`, surfaces also `#RRGGBBAA`) and **Auto** for COSMIC's derived color. Existing pending color overrides and unfinished text keep Advanced theme colors open. A complete hex color previews as soon as it is typed; incomplete text stays in the field without changing the color and is flagged on Enter, Apply or switching theme. **Type & icons:** interface and monospace font family with the weights and italic the family offers (stretch is kept), and the icon theme; both lists are searchable (opening one scrolls it into view), and a selected font or theme that is not installed stays selected and is labeled *Not installed · kept*. **Window details:** active-window outline color and width (the window gap widens to fit a wider outline, as in COSMIC Settings), roundness, density, rounded floating/tiled window corners and tiled-window shadows. **Effects** (disclosure): frosted panel/dock, applet popups, system interface and app windows, blur strength and glass opacity. Outline width, roundness, density and effects apply to both themes, like COSMIC Settings; colors apply to the variant shown. Roundness and density do not change Dock & Panel corners, padding or spacing. There is no separate text-size setting in this COSMIC version (text follows display scaling), and other toolkits follow these settings only where they read COSMIC's configuration. **System settings** opens COSMIC's own Appearance page.
  The page uses the same draft rules as Dock & Panel: nothing changes until **Apply**, drafts survive page changes, **Discard** and **Undo** work the same way, and changes made outside the editor offer **Use current value** or **Keep my change**. Only the theme roles an edit actually changes are rewritten, inside each role, so hand-customized colors and unknown settings stay. A value that contains settings this version does not recognize is shown as *kept*; an edit that would have to rewrite it is refused with an explanation rather than dropping the unknown part.
- **Motion** (`--page desktop-motion`): **Animations in apps** switches GNOME's `org.gnome.desktop.interface enable-animations`, which GTK 3/4 apps (Flatpak ones through the Settings portal) follow, and from which Firefox and Chromium-based browsers set `prefers-reduced-motion`. It is written with `gsettings` in the session's own dconf profile, read back, and applies at once like an accessibility switch. It is not part of profiles, exports or automation. **Halcyon › Interface › Slide in** (widget controls) (`sidebar_slide`, on by default) makes Desktop Cards' edge sidebar slide or appear at once. COSMIC's own window, workspace and launcher animations have no setting in this version, and libcosmic apps ignore the GTK setting; the page says so and links to Dock & Panel for the auto-hide slide. Missing `gsettings` or GTK schemas show *Unavailable*; preview mode shows the value without changing it; a fixture root keeps it in `<root>/gsettings/org.gnome.desktop.interface/enable-animations` and never runs `gsettings`. Evidence and upstream gaps: [docs/capabilities/2026-10-18-advanced-capabilities.md](capabilities/2026-10-18-advanced-capabilities.md).

Preferences are saved in `~/.config/cosmic-desktop-cards/config.json`. Settings edits preserve unrelated preferences. Rust and the controller share a file lock so simultaneous edits do not overwrite each other. Layout drafts merge only positions and grid preferences that were edited, preserving concurrent changes to untouched cards. Appearance, Clock and grid placement use backwards-compatible nested settings. Sliders preview immediately and save after a brief pause, on release, or when leaving a page; keyboard and wheel edits save too. Refresh controls wrap on smaller windows, show when a widget is paused, and include a per-widget default reset. The navigation remains reachable at the 820×480 minimum size, and the selected page stays in view in the sidebar. The settings window remains available when desktop widgets are hidden.

The devbox shows CPU utilization and temperature, memory categories, root-filesystem disk usage, physical-network download/upload rates, GPU utilization/VRAM/temperature where the driver exposes them, uptime, the local T3 service state, and Voxtype recording state. Network rates use elapsed time and per-interface byte deltas; loopback, tunnels, bridges, and inactive links are excluded to avoid double counting. A new or reconnected interface starts with “Measuring…” rather than a fabricated rate. GPU readings use sysfs on AMD; NVIDIA has a bounded, cached nvidia-smi fallback. Unsupported and sleeping devices are labeled accordingly. `T3 On` describes the local service, not the reachability of the remote tunnel. F9 remains your start/finish dictation shortcut.

Memory uses non-overlapping **used / estimated reusable cache / free** categories. Used memory gets the main accent, cache a related darker shade, and free memory the remaining track. **Used** is `MemTotal - MemAvailable`, matching modern Linux system monitors and `free`. **Cache** is the available estimate minus free memory; it represents estimated reusable memory, not the entire raw page/buffer/slab cache (some of which is counted as used). **Free** is `MemFree`, capped at `MemAvailable` when kernel reserves make less RAM available than physically unused. The compact RAM row shows just the values in that order, without category labels or repeated units. The bar always shows used and cache as two segments over the free track; turn **Show cache size** off to leave the cache figure out of the row. Optional **Swap** shows used / total capacity in smaller text on the same row; Off means no swap is configured and a dash means its reading could not be obtained. The segments add up to total RAM; small differences in rounded values or between apps can come from rounding and refresh timing. Desktop widgets do not show hover tooltips. Memory and swap values are in GiB; their compact row omits the unit suffix. Disk shows only used space against total capacity; it has no separate free-space counter. CPU temperature comes from the CPU hwmon sensor (AMD `k10temp` Tctl on this machine), not the GPU or network card.

## Desktop tools

Three optional tools sit on the desktop like the other cards: below windows, with the card palette, opacity, corners and outline from **Appearance**, no hover tooltips, and no keyboard focus. Turn each on from **Home** or **Widgets**, or with the Music · Notes · Focus row in the edge sidebar. They are placed freely like Glance: drag them in the Widgets miniature or the desktop arrangement editor (snap and guides apply); moving one never turns the default arrangement into a custom layout, and Reset returns them to their default places (Focus top center, Notes below it, Music above the bottom edge). Each page shows the real card as its preview.

- **Music** follows desktop media players through MPRIS (music apps and browsers): title, artist, artwork, position and Previous / Play–Pause / Next. Controls the player doesn't offer are dimmed; clicking the title brings the player forward when it allows that. It follows whatever is playing, else the player played last; with several open, the player name on the card switches between them for the session, and **Follow** on the Music page chooses a preferred player (kept even while it isn't running; used when it is). Follow names the app, so a browser stays followed after it restarts under a new per-process MPRIS name (`firefox.instance_1_84` is followed as `firefox`). Click **Auto** on the card to return to following playback. Browser media uses the same interface: YouTube, YouTube Music, SoundCloud and Spotify receive a site label when the browser supplies a media URL. Click the progress bar to seek when a player supplies a seekable track and duration; the request carries the visible track ID and available title/URL, checked again before seeking to protect browsers that reuse one track ID. Missing time stays visibly unknown with an inactive rail; short follow-up reads recover late browser metadata. Transport clicks keep the player and Play/Pause intent that were shown, even if automatic following changes before dispatch. Album art and progress can each be turned off. When the player stops with nothing loaded, the card keeps its full size and shows the last track it played (title, artist and player) with a Play button that resumes it in that player, or another window of the same app, while one is there to take Play; the card leaves once that player quits. The last track is kept in memory only. Before anything has played, the card says *Nothing playing*, centred; without a session bus, *Media controls unavailable*. Nothing plays, pauses or opens unless you press a control, and players are followed only while the card is shown. Artwork is read from local files or the HTTPS address the player gives (PNG or JPEG, at most 8 MiB) and kept as a small thumbnail in memory.
- **Notes** is one plain-text note. On the desktop, the pencil opens it for editing: the card rises above windows and takes the keyboard until **Save** (also Esc or Ctrl+S) or **Cancel**. Hiding Notes (Clean desktop, its switch or `toggle notes`) or arranging the desktop releases the keyboard; an unsaved draft comes back *Paused*, and only **Resume** takes the keyboard again. The Notes page has the same note with **Save** / **Revert** (Ctrl+S). Closing Settings never loses unsaved text there: it is kept privately beside the note and comes back, still unsaved, the next time Settings opens, with Widgets and Notes marked •. Only Save puts it on the desktop. The copy icon copies the saved note without opening the editor. Lines starting with `[ ]` (or `- [ ]`) are checklist items that can be ticked on the card without editing; the header shows completed / total items; `#` starts a heading and `-` a bullet. Saves never overwrite a newer edit made elsewhere: the desktop explains and saves on a second Save; the page offers **Use the desktop’s** or **Keep mine**, also for edits kept from a closed window. Two edits that arrive at the same text are simply saved. Card size is Small, Medium or Large. The note lives in `~/.local/share/cosmic-desktop-cards/notes.json` (owner-only, at most 64 KB), never in `config.json`, so profiles, exports and imports can't contain it.
- **Focus** times focus rounds and breaks: Start, Pause / Resume, Skip and Stop on the card, the remaining time, a progress bar, today’s completed rounds and dots for the rounds before a long break (a compact count for cycles longer than six). Quick lengths (15, 25, 50 minutes) are on the ready card; the Focus page sets focus (15–90 min), break, long break and how many rounds earn one (or never), plus **Start breaks automatically** and **Notify when time is up** (a desktop notification; on by default once Focus is turned on). The countdown is measured against the clock's end time, so it stays right across restarts, sleep and slow redraws; a round that ended while the computer was off or asleep shows as done without a late notification. Hiding the card (Clean desktop, its switch) doesn't stop a running round: it still ends on time, notifies and starts the break as set, with no redraws while hidden. The session (phase, end time, rounds done today) is runtime state in `~/.local/state/cosmic-desktop-cards/focus.json`, apart from the shareable preferences in `config.json`. `desktop-cards focus start|pause|toggle|reset|skip` drives it, for example from a custom shortcut.

Tool visibility lives in each tool's own section (`music`, `notes`, `focus` in `config.json`, like `glance`), not in `enabled_widgets`. Profiles therefore carry a tool only once it has been set up: its visibility and position (Layout) and card options — Music artwork and progress, Notes size (Style). Never the note, the focus session, the durations or the preferred player. Tool members require profile format version 4; dimensions require version 5; one that never mentions the tools leaves them as they are, and **Clean desktop** hides them too.

## Profile automation

**Presets → Schedules** (`desktop-cards settings --page desktop-automation`) switches between your profiles by itself: a day and an evening look, a work setup when a monitor is plugged in, Clean desktop when the projector connects. It is off until you make a rule, and nothing is scheduled on upgrade. Importing or applying a profile never turns it on.

- **Rules.** A *schedule* applies a profile at a local time on chosen days (`19:00`, `7 pm`, `0730` are all understood). A *display rule* applies one when a display connects or disconnects: a particular one (listed by its model name, including free ports for a display not plugged in yet), or the external displays as a group (the first one connecting, the last one leaving). Any built-in starting point or saved profile can be used; a rule whose profile was deleted says so.
- **Priority.** The list order is the priority: when two rules happen at once, the higher one wins. Use the arrows to reorder.
- **Your choices win.** Automation acts only when a time arrives or a display changes. In between nothing is re-applied, so your own changes stay until the next switch, and the status card says so. Pause for an hour, until tomorrow or until you resume (display rules pause too), or **Skip next** to skip only the next scheduled switch while every other rule keeps working. The last automatic switch is undone on the Profiles page like any profile.
- **Missed times.** After sleep, a restart or a clock change, only the latest missed time is applied, once, and not if you changed the desktop through Desktop Cards after it (a change in the same second counts as after). A change counts when it can be seen: an Apply on a Desktop page or a profile Apply (both leave the latest-change record), or a held widget layout saved in Settings. An Undo clears that record, so it doesn't count, and neither do changes made outside Desktop Cards (COSMIC Settings, card autosaves); those still stay until the next switch. Times from before a rule was made, edited, turned on or resumed never count, nor do times during a pause. Each local wall time happens once: the repeated autumn hour doesn't switch twice, and a time inside the spring gap happens when the clock jumps. Time-zone and clock changes are noticed within a minute.
- **Displays settle first.** A change counts once the connected displays stay the same for 5 seconds, so a dock bringing up its monitors or a monitor waking up makes one switch, not several. Displays are read from DRM (`/sys/class/drm`); the compositor's output events prompt a look, with a check every minute while a display rule is on.
- **Same engine.** A switch plans and applies the profile exactly like Apply on the Presets page: the same checks, conflict detection, recovery journal and Undo record (labelled *(automatic)*). A part that can't be applied, such as a moved wallpaper picture, is left out and named; the rest applies. A missing profile, an interrupted change waiting on the Presets page, or preview mode stops the switch with a reason in **Recent**. While Settings is open with unapplied changes to a part the switch would change, the switch waits. **Discard** them and it runs; **Apply** them and your changes win: the switch is skipped (*Kept your changes*), as it is after any change you make meanwhile. A newer switch replaces one that waits, so a waiting switch never undoes a newer one. If that Settings window closes or crashes, the wait ends by itself within seconds. Reopening keeps saved drafts on their original baselines; scheduled changes while closed are treated as external changes and checked before Apply.

Files, beside the profile library: `automation.json` (the rules, written by Settings), `automation-state.json` (what happened and what was handled, written by the desktop) and `automation-hold.json` (the parts Settings has unapplied changes to while automation is on; after a held widget layout is saved it keeps only that save's time, so a switch that was waiting still keeps the layout when Settings has closed or the desktop was stopped). None is part of a profile, an export or `config.json`. With a fixture root (`DESKTOP_CARDS_DESKTOP_ROOT`) they live in its `state` folder and display names come from `<root>/outputs`, `<root>/output-names` (`DP-2=Dell U2720Q`) and `<root>/ports`; with only an alternate configuration, automation is read-only and inactive.

In capture mode the settings command file accepts an `"automation"` list on this page: `{"new":"schedule"|"display"}`, `{"edit":"r2"}`, `{"time":"21:30"}`, `{"day":5}`, `{"change":"disconnect"}`, `{"display":"HDMI-A-1"}` (or `null` for the group), `{"preset":"glass"}`, `{"saved":"<id>"}`, `{"enable":true}`, `{"pause":"next"|"hour"|"today"|"resume"}`, `{"delete":"r1","confirm":true}`, `"save"`, `"cancel"`, `"resume"`, `"refresh"`; anything that writes needs a fixture root.

## Work calendar

Open **Settings → Widgets → Calendar → Connect Google Calendar**. Sign in in your regular browser and approve read-only access; then choose a calendar from the dropdown. Reconnect, switch accounts, check the connection or disconnect from the same page. The app stores its refresh token in Linux Secret Service, separate from preferences and exported profiles. Disconnect clears its local agenda cache without deleting Google events.

A distributed build needs a publisher-owned Google Desktop OAuth client with the Calendar API enabled. See [the publisher setup guide](google-calendar-setup.html); pass `--google-oauth-client PATH` to the installer or import the JSON under Calendar’s advanced options. An unconfigured build says so explicitly. End users of a configured release do not need Google Cloud or an MCP service. Existing installations with this app’s old calendar cache keep their Workspace integration during upgrades. New installs do not borrow those credentials.

The calendar only reads Google Calendar events. Recurring instances are expanded by Google; cancelled/declined events, out-of-office blocks and working-location entries are omitted.

The default card shows **Today**. In **Settings → Calendar**, enable **Tomorrow** to show both days as labeled sections, or turn Today off for a tomorrow-only overview. Both switches are independent. Turning both off leaves the week strip available for browsing individual dates.

The Monday–Sunday strip remains above the agenda. **↑ / ↓** browse previous/next weeks; clicking a date shows that single day. **Today** (or **Overview** when using a customized view) returns to the enabled Today/Tomorrow sections. Today hides finished timed events behind **Earlier · N** in both Calendar and Daily overview. After the final event it says **All done for today**; Earlier reveals the completed events and Hide earlier collapses them again. All-day events stay visible, and browsing past dates always shows the full day. The overview follows midnight, including month/year boundaries. The agenda grows with its content up to the available desktop space, or fills a user-selected size; busy days scroll when needed.

Events appear in a compact timeline, with lightly tinted rows and an inline **Join ↗** link beside the event title. Structured video links are preferred; recognized meeting links in an event’s description/location are a fallback. Only the resulting link is retained, not the description. Clicking a title opens the calendar event; clicking **Join** opens its meeting URL without automatically joining a call. The date controls and sync footer stay fixed; only the event list scrolls when needed. On very short displays the whole card scrolls so all controls remain reachable.

Timed events, including in-person meetings, turn amber during the last **10 minutes** before starting, with an **In N min** label; ongoing meetings show **Live now**. The Calendar control also highlights when the sidebar is open. The screen edge remains invisible. Change the lead time from 1–60 minutes in Settings. No reminder popups or sounds are generated.

The footer shows the account and a small time, without a Synced prefix; **↻** requests a refresh. A saved-data label marks a failed refresh. Weather, Calendar and Projects timestamps include a date when the data is from a previous day. Cached event titles, times and links are stored in owner-only `~/.cache/cosmic-desktop-cards/calendar-YYYY-MM.json` files. Monthly fetches cover the surrounding weeks for smooth date navigation.

## Project status

Choose project folders in **Settings → Widgets → Projects**. There are no assumed scan roots on a new installation. The Projects card discovers Git repositories under the folders you add, plus their linked worktrees. It shows the current branch, changed/untracked paths, conflicts, and ahead/behind counts from the existing local tracking refs. It never commits, fetches, checks out, or edits a repository.

Each repository appears once with a human-readable title, a compact branch label, change/conflict status, and live-server links. Linked worktrees are grouped by repository identity; checkout paths and generated hashes are not displayed. The title opens the most relevant local checkout, prioritizing conflicts, active web servers, edits, and recent activity. Click **N branches ↓** (or **N checkouts ↓** when branches repeat) to reveal each checkout’s branch and local changes. ## Build and development

Use Rust **1.93.0**, the version used by [CI](../.github/workflows/ci.yml), and
preserve `Cargo.lock`. CI lists the native build and packaging dependencies and
is the authoritative per-commit check list.

```sh
cargo +1.93.0 build --release --locked
CARGO_PROFILE_DEV_DEBUG=0 cargo +1.93.0 test --locked --bin halcyon -- --test-threads=1
```

For a focused change, insert a Rust test filter before `--`, for example
`settings::city_search::`. Keep `--test-threads=1`: some fixtures isolate
process-wide state by re-executing the test binary. Add `--offline` when the
locked dependencies are already cached. Reuse the same `CARGO_TARGET_DIR` and
profile instead of rebuilding in several target directories.

The optimized program is `target/release/halcyon`, or
`$CARGO_TARGET_DIR/release/halcyon` when configured. Use that build for interactive
performance checks; unoptimized development builds are noticeably slower.
Per-user installation is described [above](#install), and Debian development
packages use the [explicit development mode](../packaging/README.md#build-mode).

Run the Python, collector, metadata and Islands-core checks listed in CI when
changing those areas. The controller transaction tests need
`HALCYON_TEST_BINARY` set to the built `halcyon` executable. Discovery in `scripts`
alone does not include `scripts/apt`, `scripts/compatibility`, `scripts/usage`,
`companion` or the separate packaging directories. APT tests use the isolated
user namespace shown in CI; do not substitute a live system install.

Additional acceptance is documented in [compatibility](COMPATIBILITY.md),
[APT operations](APT-OPERATIONS.md), [usage reporting](../scripts/usage/README.md)
and [future-builder probes](future-builder/probes/README.md). These remain
separate from unit-test success.

The settings window watches configuration and command files instead of redrawing
on a one-second timer. A 30-second content check recovers missed filesystem events;
unchanged files do not wake the UI. Desktop settings apply as soon as the file changes.
Service status is checked only on the General page, every 30 seconds or after an action.
Disabled widgets pause their background jobs. A deadline timer wakes only when the next
visible widget needs work; requests in flight cannot queue duplicates. System sampling
runs on a background worker, the CPU sensor path and weather HTTP client are reused,
and settings stay in memory between file-change notifications. A malformed or temporary
missing config file preserves the last valid in-memory settings. Network failures retry
after two minutes. Existing in-flight jobs can finish; stale project-folder results are ignored.
Small bundled wallpaper previews avoid processing full-resolution wallpapers in Settings.
Weather also keeps an atomic, location-checked cache in `~/.cache/cosmic-desktop-cards/weather.json`,
so the last successful forecast survives an app restart. Weather attribution remains available in Settings. Saved forecasts use their actual dates instead of relabeling stale
forecast days as Today/Tomorrow. The native Clock surface is created after Calendar in the
bottom layer, preventing Calendar's full-height COSMIC backdrop from covering the clock.
Clock remains click-through and all cards remain below application windows.
Desktop surfaces disable automatic compositor blur so transparent clock areas and rounded card corners do not produce rectangular backdrops.

Generate wallpapers with `scripts/wallpapers.py`, using Python with numpy and Pillow. The supplied wallpapers were generated from the source; they contain no baked-in widgets or text.

Set `DESKTOP_CARDS_CONFIG` to an alternate JSON file for isolated layout testing. With this override, desktop runtime commands use `desktop-command.json` beside that file, so a preview cannot send commands to the normal desktop service. Set `DESKTOP_CARDS_CAPTURE_DIR` to capture the rendered native surfaces as RGBA + size JSON on theme/weather/calendar/project/layout changes, without hiding other application windows. These are development controls and are disabled in normal startup.

The desktop publishes its actual widget sizes and active output dimensions to `$XDG_RUNTIME_DIR/desktop-cards/layout-state.json` for the Settings miniature. An alternate configuration places this snapshot beside that configuration. Publication is atomic and ordered; unchanged geometry does not trigger a settings refresh. With no snapshot available, the preview starts at 1920×1080 using estimated card sizes.

Home, Layout and desktop arranging use the same fine grid with a 12-logical-pixel pitch on every display. Grid snapping includes the actual right and bottom boundaries as targets when the final grid cell does not fit exactly. Glance stores its top edge independently of its content height, so new events do not move the clock upward. Both editors retain symmetric safe insets of 24 pixels horizontally and 48 pixels vertically. Saved positions use normalized coordinates, so widgets remain within the active output after a display-size change. Older grid preferences remain readable without moving saved positions. Optional `widget_sizes` entries store `[width, height]` in logical pixels; absent entries retain automatic content sizing. **Fit content** removes a selected override; **Reset layout** previews automatic sizes and positions for visible cards. Explicit dimensions are bounded by the active screen and usable per-widget minimums. Sized cards fill their native surfaces, reflow at the new width and keep long content scrollable. Calendar and Daily overview keep all agenda events reachable; automatic Daily overview continues growing downward. Resized layer surfaces are recreated to avoid the pinned renderer’s Size-action height bug.

### Desktop settings adapter

Dock & Panel, System appearance, Windows and Workspaces read and write COSMIC's own per-key files (for example `~/.config/cosmic/com.system76.CosmicPanel.<Name>/v1/<key>`, `com.system76.CosmicTheme.{Dark,Light}[.Builder]/v2`, `com.system76.CosmicTheme.Mode/v1`, `com.system76.CosmicTk/v1` and `com.system76.CosmicComp/v1/appearance_settings`, plus the window behavior and `workspaces` keys listed under *Windows and Workspaces*), falling back to the installed defaults in `$XDG_DATA_HOME/cosmic` and `$XDG_DATA_DIRS/cosmic`, exactly as COSMIC does. Opening the editor only reads. Apply writes just the keys you changed, each atomically, after checking that none of them changed since the draft began; other keys, unknown files and other namespaces are left alone. Only a fixed list of panel, appearance, window and workspace keys can be written, and new values must parse exactly as the pinned upstream types (`cosmic-panel-config`, `cosmic-theme`, CosmicTk, `cosmic-comp-config`). Keys a change was derived from but does not write are checked too, so a change made elsewhere to an input (say, the background an accent derivation used) is reported instead of producing mismatched colors. **Match COSMIC colors** and **Matching wallpaper** (`--apply-palette-links <palette> [--wallpaper] [--colors]`; `--apply-cosmic-colors <palette>` remains as the colors-only form) use the same derivation, lock, journal and rollback, and both parts are one change; it still keeps the first `cosmic-colors-original.json` backup and takes its older lock as well, and it waits while an interrupted change is pending. A read-only store, or a fixture whose locks, journal, backup or written keys would resolve outside its root, is refused before that lock or backup is created. Before writing, the change is recorded in the journal above; a failed write restores the touched keys. If the app stops part-way, Dock & Panel shows *An earlier change was interrupted* with **Restore previous** (keys still holding the interrupted values return to their earlier values; keys changed since are kept) or **Keep current**. Apply waits until one is chosen. The choice is offered right away when a failed write could not restore every key; the unapplied draft is kept.

**Undo and ownership.** Dock & Panel, System appearance, Wallpaper, Desktop icons, Windows, Workspaces, Floating apps, Shortcuts and profiles record their latest applied change in `desktop-undo.json`, inside the same locked transaction, just before the journal is removed. Undo therefore works after a restart. A page offers Undo only when the latest change is its own, never while an interrupted change is waiting to be restored or kept, and never for a newer change made elsewhere. A failed Apply keeps the previous entry. The entry takes part in the transaction: the journal keeps it exactly as the change found it, so if the app stops after a change replaced or an Undo cleared it, **Restore previous** puts the earlier entry back (an entry changed elsewhere since is left alone), while **Keep current** keeps the entry the change left. An entry that can't be kept that way (not text, or too large to journal) stops the change before anything is written. A damaged entry, or one from another version, is explained and not used; the next successful change replaces it. **Match COSMIC colors** neither replaces nor clears it.

### Windows and Workspaces

**Desktop → Windows** (`desktop-cards settings --page desktop-windows`) edits COSMIC's window behavior: automatic tiling and what it applies to, window gaps, the active-window outline, the minimize and maximize buttons, focus follows pointer (with its delay), pointer follows focus and edge snapping (its distance is under **Advanced**). **Desktop → Workspaces** (`--page desktop-workspaces`) edits orientation, separate or shared workspaces across displays, wrapping, and what typing in the overview does. Each page has a small diagram that follows the draft, and the same Apply / Discard / Undo footer as the other desktop pages; opening a page only reads.
- Keys: `com.system76.CosmicComp/v1` `autotile` (default off), `autotile_behavior` (`Global` default or `PerWorkspace`), `active_hint` (on), `focus_follows_cursor` and `cursor_follows_focus` (off), `focus_follows_cursor_delay` (250 ms), `edge_snap_threshold` (0 = off; switching it on uses 10 like COSMIC Settings) and the single `workspaces` struct (`workspace_mode` `OutputBound`/`Global`, `workspace_layout` `Vertical`/`Horizontal`, `action_on_typing`, `workspace_wraparound`); `com.system76.CosmicTk/v1` `show_minimize` and `show_maximize`. Defaults are COSMIC's own and used only when no layer defines a key; a value this version can't decode is shown as it is and that control can't be changed.
- The workspaces struct is always rewritten whole from its decoded current value, so the members you didn't change keep theirs. A struct with an unknown member or value, or malformed text, is never rewritten. Pinned workspaces, display assignments and input/keyboard settings are never touched.
- **All workspaces** (Global) applies tiling everywhere and rearranges existing windows; **Each workspace** (PerWorkspace) sets the default for new windows and workspaces. COSMIC reads tiling and its scope as separate keys and retiles existing windows whenever the scope it holds is Global, so changing both in one step is refused. The page offers the first of two Applies, chosen so the scope in between is Each workspace: **Apply scope first** when the new scope is Each workspace, **Apply tiling first** when it is All workspaces. That step writes only its own key, and nothing if the other one changed outside the editor meanwhile; your other edits stay in the draft, still checked against the values they started from, for the next Apply. Each step is its own Undo, and Undo restores the settings, not window positions.
- Window gaps belong to each theme (`gaps` in the Light or Dark builder and theme, as `(outer, inner)`, at most 500 px). The page edits one theme at a time without changing the light/dark mode; a gap between windows you change is never below that theme's outline width (dragging it lower onto the current value is no change), and changing only the screen-edge gap keeps the other exactly, even one below the outline. If System appearance has unapplied changes to the same theme, Apply and Undo on either page wait and link to the other page; changes to the other theme, or to window behavior, don't wait.
- Typed numbers (focus delay 0–10000 ms, snap distance 1–200 px) must be whole numbers in range before Apply.

### Wallpaper & colors and Desktop icons

**Desktop → Wallpaper & colors** (`--page desktop-wallpaper`) edits cosmic-bg's `com.system76.CosmicBackground/v1` keys: the shared background (`all`), **Same background on all displays** (`same-on-all`), and per-display backgrounds (`output.<connector>` plus the `backgrounds` list) through display chips; **Use the shared background** takes a display off the list and leaves its file alone, as COSMIC Settings does. The header shows the selected display's background as cosmic-bg would draw it (Fill, Fit with its letterbox color, Stretch; gradients blended in linear light), a slideshow's current picture and its interval. The gallery has **Desktop Cards** (the six bundled wallpapers at `~/Pictures/Desktop Cards`, with **Reinstall bundled wallpapers** when one is missing), **COSMIC** (pictures in the system `backgrounds` folders and the folder as a slideshow), **Yours** (pictures and folders added with **Add picture** / **Add folder**, saved only in `wallpaper-collection.json` in the app's state folder with mode 0600; COSMIC Settings' own custom images, read only; and personal pictures in use) and **Solid & gradient** (COSMIC's background colors and gradients, plus a custom color or 2–3 color gradient with a direction). Slideshow folders offer the interval and order; folders are counted with a bounded scan. **Follow wallpaper colors** is the main color control. Turn it on and Apply once: the running desktop app follows later wallpaper changes even with Settings closed, including the current slideshow picture and changes made outside Desktop Cards. It starts off on existing installations. The recommended accent is selected automatically; click one of the offered colors (the picture's distinct hues, each toned to a lively, readable accent) or edit its `#RRGGBB` value to adjust the current wallpaper without turning the link off. **Use recommended** returns to the suggested color; the next wallpaper or slideshow frame chooses a fresh recommendation. Turn the switch off to keep a fixed color; the six palettes are under **Fixed palettes**. The same color source is used in Settings and on the desktop: a connected built-in display first, otherwise the first connected connector alphabetically, or Shared background when no display is connected. With several displays the color card names that source, even when you preview a different display. With **Widgets + Pop!_OS**, **Apply** saves a staged wallpaper, the app’s chosen color and both COSMIC theme accents in one transaction; **Widgets only** leaves COSMIC themes unchanged. Color-only changes preserve the current wallpaper. **Undo** restores the combined change. Widget style and Theme & fonts link here instead of duplicating the common color controls. Fonts, light/dark mode, outlines and other independent theme edits stay pending and can apply before or after wallpaper colors. Derived theme files are merged from their semantic inputs; external changes to the edited input still require resolution. A recovered per-theme accent can be finished in Theme & fonts or replaced explicitly with **Use this color**, keeping other edits. **Keep my color** resolves an external color conflict without discarding the wallpaper draft. **Choose picture…** stays available in the preview header on every collection tab. Previews and extracted colors refresh when a picture is replaced at the same path or the slideshow picture changes. Settings changes remain drafts until Apply; opening, previews, scans and suggestions write nothing. After the automatic link is enabled, the existing Cards runtime decodes colors off the UI thread, debounces changes, rejects stale results, and applies widget and desktop colors through the same guarded, recoverable transaction. Missing, unreadable and unsupported pictures keep the last valid colors and show a reason on this page. A newly selected slideshow with no reported frame keeps its colors until cosmic-bg reports the first picture. Pending wallpaper/color choices, recovered per-theme accent input and preset previews pause automatic writes, including after Settings closes. Independent font, outline and window drafts do not pause the link. In Widgets only scope, native theme input does not pause widget colors. Offered colors keep the picture's hue at a visible lightness, so a dark picture never suggests one of its dark pixels; a typed hex color remains exact for the widgets. With **Widgets + Pop!_OS**, COSMIC gets one tone of that color per variant (pastel in Dark, deep in Light). If the active window outline has its own color, including one only COSMIC's derived theme holds, the Color card says so and **Match accent** makes it follow the accent with the same Apply and Undo. With a theme applied, the Color card shows the theme's color in one line and links to Themes, where colors are chosen; a wallpaper applied here also gets the theme's matching wallpaper text contrast in the same Apply, and a grey one keeps the theme's own color. A profile with explicit colors selects fixed mode unless it explicitly carries an automatic-color choice; wallpaper-only profiles keep the link. Automatic colors respect Undo until the next wallpaper, including after restart. The desktop widget process must be running for the automatic link to update. Only PNG and JPEG are previewed (at most 64 MiB, 16384 px per side); other formats cosmic-bg shows are selectable with *No preview*. Not supported, so not offered: a crop region or anchor, tiling, spanning one picture across displays, the light/dark theme filter and the resampling filter (cosmic-bg ignores both).

**Desktop → Desktop icons** (`--page desktop-icons`) edits `com.system76.CosmicFiles/v1/desktop`: icon size and spacing (50–500 % in steps of 25; spacing applies in both directions) and whether the desktop shows the Desktop folder, mounted drives and the trash, with a schematic of the draft (the desktop's top-left corner, enlarged). COSMIC Files stores an outside change at once but draws the desktop with it only at its next refresh (for example after signing out and back in), so the page says so; there is no refresh button. Without `cosmic-files-applet` the page explains that COSMIC Files isn't installed.

Capture mode accepts a `"wallpaper"` list (`{"tab":"colors"}`, `{"page":1}` (the gallery page, from 0), `{"select":{"bundled":"teal"}}`, `{"select":{"color":"#336699"}}`, `{"select":{"gradient":["#FF8800","#3366CC"],"angle":90}}`, `{"fit":"fit"}`, `{"fit_color":"#202020"}`, `{"same":false}`, `{"display":"DP-1"}`, `{"every":900}`, `{"order":"shuffle"}`, `"use_shared"`, `"suggest_accent"`, `"apply"`, `"discard"`, `"undo"`, `"use_current"`, `"recover"`, `"keep"`) and a `"desktop_icons"` list (`{"size":150}`, `{"spacing":75}`, `{"show":["trash",true]}`, `"apply"`, `"discard"`, `"undo"`). With a fixture root, `dir/outputs` lists displays, `dir/backgrounds` is the system backgrounds folder, `dir/pictures/Desktop Cards` the bundled pictures and `dir/cosmic-state/com.system76.CosmicBackground/v1/wallpapers` cosmic-bg's slideshow state (never the live one). A selected animated WebP or APNG is marked *Animated · shown still*: cosmic-bg decodes one frame and has no animated or video source, so slideshows are the supported moving background. A `"motion"` list drives the Motion page (`{"animations":false}`, writing only with a fixture root; `{"slide":false}`; `"refresh"`).

### Floating apps and Shortcuts

**Desktop → Floating apps** (`--page desktop-window-rules`, also linked from Windows) lists COSMIC's tiling exceptions: windows that open floating while automatic tiling is on. COSMIC rebuilds its matcher when the rules change and checks it when a window opens, so a change affects windows opened afterwards; windows already open keep their place.
- Keys: `com.system76.CosmicSettings.WindowRules/v1` `tiling_exception_defaults` (COSMIC's defaults, read-only, never written) and `tiling_exception_custom` (your rules). Defaults are expanded in order, and a custom rule with exactly the same app-id and title strings switches that default on or off; other custom rules are added. Each row shows the app (name and icon from its desktop entry when the ID matches one), the title condition, *Default*, *Default · changed* or *Custom*, and its switch. Switching a default off writes a custom override; **Restore** removes it. A default COSMIC lists twice can't be switched off this way (an override reaches only the first copy) and says so.
- COSMIC matches the app ID and the title as unanchored Rust regular expressions (the `regex` crate at the compositor's version), and a rule applies only when both match. **Add app** takes an exact app ID (written as `^…$` with special characters escaped) or one chosen from the installed apps, and an optional *Title contains* text (escaped; empty means any title). The suggested ID is the entry's `StartupWMClass`, else its desktop ID, and stays editable; nothing is launched or probed. **Use patterns** accepts raw expressions, checked with the same engine. Existing patterns are shown and edited as patterns, never turned into text. A rule that already exists, an invalid pattern, or one that would float every window is refused in the form.
- The custom list is rewritten whole, in order, from its exact decoding. Lists are read the way COSMIC reads them: members this version doesn't know are skipped, so such a list (custom or default) is shown with the rules COSMIC applies, and a custom list like that is kept as it is and can't be changed here. Text that can't be read at all is ignored by COSMIC; it is shown that way and never rewritten.

**Desktop → Shortcuts** (`--page desktop-shortcuts`) lists custom commands and COSMIC's built-in shortcuts with keycaps, searchable and filtered by All, Custom or Built-in.
- Keys: `com.system76.CosmicSettings.Shortcuts/v1` `defaults` (read-only) and `custom`, maps from a binding to an action; a custom entry overrides the default with the same modifiers and key. A binding's name (`description`) and any hardware `keycode` are kept but are not part of its identity, as in COSMIC. `system_actions` is never touched.
- **Add** creates a named command: type the combination (for example `Super+Shift+K`; key names are xkbcommon keysym names, single letters are case-insensitive). The same combinations COSMIC Settings accepts are allowed: modifiers with a key, Super alone, or a function, media or navigation key alone. Combinations are typed; there is no key recording. If the combination is already used, the form names what it does and offers **Replace** or **Cancel**; nothing changes until Replace, and nothing is written until Apply. A question holds only for the shortcuts it was asked about: if they change meanwhile (another tool, Refresh, **Use current**), earlier answers are dropped and the question is asked again about what is there now; the typed form stays. Commands are stored exactly as typed and are never run by Desktop Cards.
- Each custom command has a switch. Off writes COSMIC's `Disable` for that combination and keeps the command in Desktop Cards' own key `io.github.workstation.DesktopCards.Shortcuts/v1/disabled_commands` (local state, a strict list of `(binding, command)`); on restores it. Both keys change in the same Apply and are undone together. If something else took over a paused combination meanwhile, the paused command keeps its own row: switching it on, or saving an edit to it at that combination, asks to **Replace** first, and removing it deletes only the paused command, never what uses the combination now.
- Removing a command, or moving it to another combination, never brings a built-in default back silently: the page asks whether to **Turn it back on** or **Keep … off**. Built-in shortcuts can be switched off and on; **Restore default** removes a custom override.
- Untouched entries keep their exact text, including actions this version doesn't recognize (COSMIC treats those as off) and Super-only or modifier-only bindings. A custom file with an unknown binding field, unreadable text or RON extensions is never rewritten; a combination listed twice shows both copies, and edits wait until **Remove this copy** resolves it. Bindings with a hardware keycode are kept and labelled; COSMIC's matcher ignores the keycode itself but still runs the binding on the modifiers and key shown (or the modifiers alone), so they can't be created or edited here.
- Floating-app rules, shortcut commands and names, and paused commands are local: they are never captured, exported or applied by profiles.

### Desktop profiles (core)

A profile is a versioned JSON record (`"format": "desktop-cards-profile"`, `"version": 5`) with optional `dock`, `panel`, `appearance`, `windows`, `workspaces`, `wallpaper`, `desktop_icons`, `widget_style` and `widget_layout` sections. Every member is optional, and absent means the profile leaves that setting alone. A record with `widget_sizes` is written as version 5 (including `null` for automatic dimensions), one with desktop tool members as version 4, one with `wallpaper` or `desktop_icons` as version 3, any other as version 2, so older versions keep reading what they can. Version 1–4 records (older exports, library copies and the built-in presets) are still read as they are; they can't contain a later version's members.
- Light and Dark theme values are kept separately: colors as `"auto"`, `#hex` or exact components; corners and spacing as a preset name or exact values; blur; glass as a percentage or an exact alpha map; frosted surfaces; window `gaps` as `[outer, inner]`.
- `windows` uses COSMIC's key names (`autotile`, `autotile_behavior` as `"global"`/`"per_workspace"`, `active_hint`, `focus_follows_cursor`, `cursor_follows_focus`, `focus_follows_cursor_delay`, `edge_snap_threshold`, `show_minimize`, `show_maximize`); `workspaces` uses the struct's member names with snake-case values (`"output_bound"`, `"horizontal"`, `"open_launcher"`, …). Gaps stay in Appearance because they are theme values. A profile whose Windows part would change both tiling and its scope is refused for that part; it names the first step to apply on the Windows page (the scope when it becomes Each workspace, tiling when it becomes All workspaces), after which the profile applies.
- `wallpaper` has `background` (the shared background, which displays without their own also show) and, in local profiles only, `displays` (`"same"`/`"separate"`) and `per_display` (`{"<connector>": background}`). A background has a `source` — `{"bundled":"lavender"}`, `{"system":"cosmic/<file or folder>"}` (relative to a system `backgrounds` folder), `{"color":"#RRGGBB"}`, `{"gradient":{"stops":[…],"angle":0–360}}`, and locally `{"image":"/abs"}` or `{"folder":"/abs"}` — plus `fit` (`"fill"`/`"fit"`/`"stretch"`), `fit_color` and, for folders, `slideshow` (`{"every":seconds,"order":"in_order"|"shuffle"}`). Colours that aren't 8-bit exact keep exact components (sRGB; gradient stops in linear light, as cosmic-bg stores them). Members cosmic-bg stores but doesn't use (`filter_by_theme`, `filter_method`) are never part of a profile.
- `desktop_icons` has `icon_size` and `spacing` (1–500 %, any value COSMIC Files accepts, also between the page's 25 % steps), `show_folder`, `show_drives` and `show_trash`.
- The widget sections use config.json's own member names, limited to a fixed allowlist: palette, card look, clock/Glance/Devbox/calendar and tool card options, visibility, order, positions and snap.
- Profiles never contain monitor assignments (the Dock/Panel `output`), pinned workspaces, keyboard or input settings, location, project folders, accounts, calendar data, refresh intervals, palette-matching links or commands, and never contain floating-app rules (they can hold private window titles), shortcuts or paused commands. The only paths are a local profile's own wallpaper pictures.

**Shared and local profiles.** Exported files and imports are shared profiles: they carry built-in, COSMIC, colour and gradient wallpapers, never this computer's own pictures, display names or arrangement. Export leaves those out and says what stayed ("Kept on this computer: your own wallpaper, display-specific backgrounds"); a background whose own picture is left out goes as a whole, with its fit and slideshow, so it can't change someone else's current wallpaper, and a wallpaper section left empty goes too. Import refuses a file that refers to pictures or displays ("This profile refers to pictures or displays on another computer…"). Saved profiles in the library are local and keep everything.

Capturing reads the applied desktop: the effective shared background (a bundled wallpaper by palette name; a COSMIC wallpaper only when it resolves inside a trusted system backgrounds folder without an escaping link — pictures in your home or data folder stay personal; otherwise your own picture or folder, noted when it's missing), the display arrangement when every listed display has a readable background of its own (otherwise it is left out with a warning rather than captured in part), and the desktop icon values exactly. Importing parses bytes and stores nothing. Exporting writes only the record. Newer versions, unknown sections or members, recovery records and oversized or out-of-range values are refused with a reason.

A **plan** previews exactly the selected parts and writes nothing. While a selected part is blocked the footer says *Leave out the blocked part to apply the rest* (or *Can’t apply this profile yet*), never that the profile matches; after an Apply that changed desktop icons, the page repeats that COSMIC Files shows them after its next refresh.
- A selected part the profile lacks, a Dock/Panel that isn't set up, or a current value this version can't decode blocks that part. The other parts can still apply once it's excluded.
- Fonts and icon themes that aren't installed are named and not written: the current one is kept. Applets that aren't installed are named and left out. The saved profile keeps all of these identifiers.
- Wallpaper and Desktop icons are planned through the Wallpaper and Desktop icons pages' own drafts: the same validators, write order and preservation. Profiles never change the wallpaper unless the profile has a Wallpaper part and it is included. A picture or folder the profile would newly show that isn't available (a built-in wallpaper not installed, a COSMIC wallpaper not on this computer, a moved picture, an empty folder), or a current background this version can't rewrite, blocks only the Wallpaper part; leave it out to apply the rest. Present `displays`/`per_display` replace the arrangement: exactly the listed displays get their own background (one not connected is kept for when it is), and a mode without a map means none; when both are absent the arrangement is left alone, and displays with their own background keep it.

**Apply** writes the COSMIC keys and the widget members as one recoverable change:
- Lock order: `config.json.lock` (shared with the controller), then `desktop.lock`.
- Every original is re-read under the locks. One journal covering both parts is written before the first change.
- On failure, everything that is still ours is restored. An interrupted change is restored by **Restore previous** after a restart.
- Unrelated and unknown widget settings are left as they are. Undo and recovery give back the widget file's exact earlier bytes when nothing else changed it; otherwise only the settings the profile wrote, keeping newer edits.
- The wallpaper pictures and folders the plan resolved are checked again just before anything is written (a COSMIC wallpaper must still resolve inside its trusted folder); if one is gone, nothing is written and the Wallpaper part shows why. No other picture is chosen instead.
- Applying a profile never runs palette or wallpaper matching.

Named profiles are stored under generated IDs: equal names never share a file. Listing them creates nothing, and a symlinked library folder is refused.

### Profiles page

**Presets** (`desktop-cards settings --page desktop-profiles`) offers four built-in starting looks and your saved profiles. Selecting one only previews it: a miniature of your desktop with that look — on the profile's wallpaper when its Wallpaper part is included and can be applied, otherwise on a neutral backdrop — plus the parts it would change, each with a count. The wallpaper picture is made in the background, never while drawing. A blocked part offers **Leave out**, and a profile with your own pictures or display arrangement says that Export leaves them out. Turn parts off to keep them as they are. Blockers and missing components stay visible; **Show details** lists every change. Nothing is written until **Apply**, which applies exactly the listed plan; **Undo** reverses the latest profile change, also after a restart.
- **Minimal**: Graphite cards and accents, a transparent compact Glance with only the clock, and a small floating dock.
- **Glass**: Lavender, frosted panel and applets with blur, translucent dock, panel and cards. Fonts, icons and Light/Dark mode stay yours.
- **Workbench**: Ocean, solid cards, Projects and Devbox shown, Devbox histories off, a comfortable Glance.
- **Clean desktop** (stable ID `presentation`): every card and tool hidden (Glance's calendar and weather sections off too) and the dock set to hide. It does not silence notifications or change any system presentation mode.

Presets are plain profile records, validated like an imported file, and leave fonts, icon themes, monitor assignments, applet arrangements, locations, projects and palette-matching links alone. **Save current…** captures the applied desktop under a name; **Duplicate**, **Rename**, **Export…**, **Import…** and **Delete…** manage local copies (built-ins can be duplicated and exported, never changed). Import reads at most 256 KiB from a local file chosen in the system file chooser and stores a validated copy without applying it; Export writes only the portable record to the chosen file (the chooser asks before replacing), through a temporary file and a rename. A dialog result only completes the request that opened it.

If Wallpaper & colors, Dock & Panel, Theme & fonts, Desktop icons, Windows, Workspaces or the Widgets layout has unapplied changes in a part the profile would change (shared colors hold Widget style and, when syncing, Appearance; window gap drafts count as Appearance; an unfinished colour code on the Wallpaper page counts too), Apply waits and links to that page; those drafts are never discarded or saved for you, and drafts in other parts are kept. Pending card-style autosaves are saved first. If the desktop changed after the preview, Apply reports the conflict and **Refresh preview** plans again. The latest change has a single Undo slot: each page shows the latest change's name and links to the page that made it, and never undoes another page's change. Restore after an interrupted change names anything kept because it changed since, including widget settings and the saved Undo entry.

In capture mode the settings command file also accepts a `"profiles"` list on this page: `{"select":"glass"}` (a preset ID, a saved profile's name or `"current"`), `{"include":["dock",false]}`, `{"capture":"Name"}`, `{"duplicate":"Name"}`, `{"import":"file.json"}` (a file inside the fixture root only, without a dialog), `"details"`, `"discard"`, `"replan"`, `"apply"`, `"undo"`, `"recover"`, `"keep"`. Writing actions need a fixture root; no capture action exports a file.

On **Themes**, the same capture flow accepts `{"select":"soft"|"outline"|"paper"|"bare"}`, `{"wallpaper_colors":true}`, `{"matching_wallpaper":true}` and `{"reset":"widget_style"|"dock"|"panel"}`. Save current captures appearance only and Import refuses broader layout presets. All writing actions still require an isolated fixture root.

## Further COSMIC customization

COSMIC supports desktop colors, fonts, icons and coordinated application themes; dock/panel visibility, opacity, size, position and applets; tiling, active-window hints, workspaces, keyboard shortcuts and display scaling. Dock & Panel, System appearance, Windows, Workspaces, Floating apps and Shortcuts edit those directly; the Desktop page links to the installed native controls for the rest. System76 documents these capabilities in [COSMIC theming](https://system76.com/cosmic/theming) and [Pop!_OS Basics](https://support.system76.com/support/pop-basics/).

What this COSMIC build cannot do, with the upstream pieces each would need, is recorded in [docs/capabilities/2026-10-18-advanced-capabilities.md](capabilities/2026-10-18-advanced-capabilities.md): animated or video wallpapers (cosmic-bg draws still frames), compositor or desktop-wide reduced motion (cosmic-comp's animation durations are fixed and the portal has no `reduced-motion`), and restoring a session or window arrangement (COSMIC starts autostart apps at login, but has no session manager or session-management protocol). Desktop Cards offers no controls for these. Google Calendar has an app-owned setup flow; public distribution still needs a registered Google Desktop OAuth client and packaging for supported COSMIC versions. Existing installations keep their local Workspace calendar connection during the upgrade.
